    Network bias¶

    The scores an attribution method gives the nodes of a knowledge-primed neural network (KPNN) depend partly on where each node sits in the graph: a node that pools many inputs can score high because it pools many inputs. The literature calls this network bias, or structural bias. It matters when you read node scores as a ranking of nodes; the model's predictions are not affected. Several papers correct for it, each in its own way, and whether to correct at all is an open question.

    This page shows how to measure the effect and how to try the published corrections with kpnn2. It does not recommend one; the section "Before you correct" says what to check before you trust a corrected score. The page builds on Mapping attributions, which explains how scores get node names, and on the model of the Feedforward example.

    The scores come from Captum, which is not a kpnn2 dependency:

    A toy network¶

    Twenty-four genes feed ten pathways, and every pathway feeds one outcome node. The pathways differ only in size, from 2 to 16 member genes drawn at random, so some genes sit in several pathways. A gene that joins no pathway is not an input node, and align_inputs() ignores its column.

    node_table() gives one row of graph counts per node. For a pathway, in_degree is its number of member genes, and here it equals n_input_ancestors, the inputs that reach it.

    Model and scores¶

    The model has one PackedLinear per hop — everything entering one layer — and a tanh between them: genes to pathways, then pathways to the outcome. pathway_scores() trains one run and scores the pathways with Captum's LayerConductance on the first hop module. map_node_attributions() names the scores, and the function returns each pathway's mean absolute score over the observations.

    Each run uses its seed for the simulated data and for generator=, so runs differ only by chance. simulate() draws standard normal genes and adds 1 to the informative genes in class 1.

    In [ ]:
    Copied! 
    class PathwayModel(nn.Module):
    def __init__(
        self,
        spec,
        generator,
    ):
        super().__init__()
        self.hops = nn.ModuleList(
            [
                kpnn2.PackedLinear.from_hop(
                    hop,
                    identity=spec.fingerprint,
                    generator=generator,
                )
                for hop in spec.hops
            ]
        )

    def forward(self, x):
        pathway_state = torch.tanh(self.hops[0](x))
        return self.hops[1](pathway_state)


def simulate(
    informative_genes,
    seed,
    n_samples=1000,
):
    """Standard normal genes; informative genes gain 1 in class 1."""
    rng = np.random.default_rng(seed)
    labels = rng.integers(
        0,
        2,
        size=n_samples,
    )
    values = rng.normal(
        0.0,
        1.0,
        size=(n_samples, len(genes)),
    )
    informative = np.isin(
        genes,
        informative_genes,
    )
    values += informative * labels[:, None]
    x_df = pd.DataFrame(
        values,
        columns=genes,
    )
    return x_df, labels


def pathway_scores(
    model_class,
    informative_genes,
    seed,
):
    """Train one run; return mean |conductance| per pathway."""
    x_df, labels = simulate(
        informative_genes,
        seed,
    )
    col = kpnn2.align_inputs(
        x_df.columns,
        spec,
    )
    x = torch.as_tensor(
        x_df.to_numpy()[:, col],
        dtype=torch.float32,
    )
    y = torch.as_tensor(
        labels,
        dtype=torch.float32,
    ).reshape(-1, 1)
    model = model_class(
        spec,
        torch.Generator().manual_seed(seed),
    )
    optimizer = torch.optim.Adam(
        model.parameters(),
        lr=1e-2,
    )
    loss_fn = nn.BCEWithLogitsLoss()
    for _ in range(300):
        optimizer.zero_grad()
        loss_fn(model(x), y).backward()
        optimizer.step()
    conductance = LayerConductance(
        model,
        model.hops[0],
    ).attribute(
        x,
        target=0,
    )
    scores = kpnn2.map_node_attributions(
        conductance,
        spec,
        hop_output=spec.hops[0],
    )
    return abs(scores).mean("observation")


def runs(
    informative_genes,
    model_class=PathwayModel,
    n_runs=5,
):
    """Scores of several runs, stacked on a seed axis."""
    return xr.concat(
        [
            pathway_scores(
                model_class,
                informative_genes,
                seed,
            )
            for seed in range(n_runs)
        ],
        dim="seed",
    )


def rank_correlation(
    run_scores,
    column,
):
    """Spearman correlation of each run's scores with a count."""
    count = counts.loc[run_scores["node"].values, column]
    return [
        round(
            float(run.to_pandas().rank().corr(count.rank())),
            2,
        )
        for run in run_scores
    ]

    Seeing the bias¶

    Fortelny and Bock (2020) train control runs on inputs in which every gene is equally predictive of the label. No pathway is special in such data, so whatever separates the pathways' scores comes from the graph. The next cell trains five such runs and prints, for each run, the Spearman correlation of the pathway scores with in_degree: the Pearson correlation of their ranks, 1 when the scores grow with the count.

    Measuring it in your model¶

    The check needs two things every kpnn2 model has: scores named by map_node_attributions(), and node_table(). Join them by node name and correlate them layer by layer. rank_correlation() above does that for any column of the table. In deeper layers, where a node's parents are other pathways, n_input_ancestors counts the genes that reach it through any path: its gene-set size in a pathway hierarchy. Betweenness and other centralities are not in the table; networkx computes them from spec.to_edgelist().

    Here the label shifts four genes. Several pathways of different sizes contain them, so the data do not single out one pathway.

    Correcting with structure counts¶

    Elmarakeby et al. (2021) divide a node's score by its degree, the number of its parents plus its children, when the score lies above the mean plus five standard deviations of its layer. They count degree from the trained weights that are not zero, which matches the graph's edges unless a weight is exactly zero. The next cell applies the division to every pathway; the five-standard-deviation condition is one Series.where() on top.

    Correcting with control runs¶

    Fortelny and Bock (2020) test each node's scores on real data against its scores in control runs; the plainest form of that comparison is a difference of means. Esser-Skala and Fortelny (2023) first quantile-normalize the scores of all runs together, so every run has the same distribution of scores, then subtract the control mean. Their control runs are trained on shuffled labels; the code takes any set of control runs.

    Scores are keyed by node name, so the control runs may come from a different spec, such as a randomized graph, as long as the node names match.

    def quantile_normalize(table):
    # Every column gets the mean of the sorted columns.
    reference = np.sort(
        table.to_numpy(),
        axis=0,
    ).mean(axis=1)
    ranks = table.rank(method="first").astype(int) - 1
    return ranks.apply(
        lambda column: pd.Series(
            reference[column.to_numpy()],
            index=column.index,
        )
    )

    Scaling inside the model¶

    Some models change the forward pass so that a node's size sets the scale of its value less. Kim and Lee (2023) divide each pathway's pre-activation by the square root of its member count, and Zhang et al. (2024) average over incoming edges. For either, node_table() gives the counts in unit order: np.repeat() by the width column turns a layer's rows into one value per unit, so the divisor also fits nodes with several units.

    In [ ]:
    Copied! 
    class ScaledPathwayModel(PathwayModel):
    def __init__(
        self,
        spec,
        generator,
    ):
        super().__init__(
            spec,
            generator,
        )
        table = spec.node_table()
        pathway_rows = table[table["layer"] == 1]
        member_count = np.repeat(
            pathway_rows["in_degree"].to_numpy(),
            pathway_rows["width"].to_numpy(),
        )
        self.register_buffer(
            "pathway_scale",
            torch.as_tensor(
                member_count,
                dtype=torch.float32,
            ).sqrt(),
        )

    def forward(self, x):
        pathway_state = torch.tanh(self.hops[0](x) / self.pathway_scale)
        return self.hops[1](pathway_state)

    Before you correct¶

    • A correction is a modeling assumption. Dividing by size assumes that a large node's extra score is an artifact. If large nodes matter, or the graph misses edges, the correction removes signal along with the artifact, and results can get worse.
    • Judge a correction by a criterion that does not depend on it: a simulation whose ground truth you set, held-out data, or agreement with independent evidence. A toy as small as this page's says nothing about your data.
    • Use several runs. Scores of single runs vary, as the per-run correlations above show. Esser-Skala and Fortelny (2023) retrain each network many times before they compare scores.
    • Report uncorrected scores next to corrected ones, and name the correction.
    • Decide how a wide node combines its units. map_node_attributions() repeats a wide node's name on each of its units and does not fold them. A sum over the units grows with the node's width, so when widths grow with degree, summing adds size back; a mean does not.

    What kpnn2 does not do¶

    kpnn2 does not simulate control data, shuffle labels, rewire a graph, or choose a correction. It provides the parts each approach needs: scores named by node (map_node_attributions()), graph counts in unit order (node_table()), seeds isolated per run (generator=), and a checkpoint check that stops a control model from loading another prior's weights (identity=spec.fingerprint). Folds of node scores that ship with kpnn2 live in the method registry of aggregate_node_attributions(); list_aggregation_methods() lists them.
