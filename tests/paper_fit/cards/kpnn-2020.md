## Summary

The model classifies single cells from scRNA-seq expression (TCR stimulation,
immune cell types, disease states in LCH, AML, glioblastoma). The prior is a
directed network of transcription factor (TF)→gene pairs and SIGNOR signaling
edges, cut to shortest paths from receptors or class nodes through signaling
proteins and TFs to genes. Every graph node is one sigmoid unit and the edges
are the only weights; genes are inputs, graph roots are outputs. Hidden nodes
are scored by finite-difference perturbation of their activation, collected
over replicate trainings and compared with trainings on control inputs.

## Prior-knowledge graph

- Source (paper only; the building code is not in the repository): TF–target
  pairs from Harmonizome (ENCODE, CHEA, ESCAPE, MotifMap, TRANSFAC) and
  TRRUST (3 July 2017), keeping each gene's best-supported TFs and dropping
  745 genes with more than 25 TFs; signaling edges from SIGNOR (3 July 2017),
  protein, complex, and family nodes only. TCR KPNN: union of all shortest
  paths from the TCR node `SIGNOR-C153` to every reachable TF, plus TF→gene
  edges. GEN KPNN: one output node per class linked to all surface receptors,
  then shortest paths to TFs, extended with receptor→TF paths only where a
  depth rule shows they add no cycle.
- Size: not in the main text (Additional file 1, not read); the edge lists are
  external data files and were not fetched. Directed, acyclic (enforced at
  `KPNN_Function.py:508`), unsigned in code (only `parent` and `child` are
  read, `KPNN_Function.py:237-244`). Node types: genes (leaves); TFs and
  signaling proteins, complexes, or families (hidden); receptors or class
  nodes (roots). Edges point regulator → target, so data flows child → parent.
- Data to nodes: `_gene` is appended to every data row name
  (`KPNN_Function.py:222`), so gene leaves in the edge list must carry that
  suffix. Inputs are the edge-list leaves (children that are never parents)
  found in the data (`KPNN_Function.py:239-240`). Data rows outside the graph
  are dropped (`KPNN_Function.py:323`). Edges whose child is neither a matched
  gene nor a parent are dropped (`KPNN_Function.py:244`). A loop then removes
  roots that are not label columns and leaves that are not matched genes until
  nothing changes (`KPNN_Function.py:258-267`). Label columns that are not
  roots are ignored (`KPNN_Function.py:248-250`).
- Built at: in Python, only the matching and pruning above
  (`KPNN_Function.py:236-272`). Edge lists are downloaded prebuilt
  (`Download_Data/Download_TCR.sh:7-10`).

## Architecture

- Layers: none. Nodes are ordered by repeatedly peeling off leaves: genes go
  first and are not ranked, hidden nodes are appended round by round, roots
  last (`KPNN_Function.py:493-510`). Each node is built after all its children.
- Units per node: one; `z = w · children + b`, sigmoid on hidden nodes, none on
  outputs, whose logits go to the loss (`KPNN_Function.py:611-620`).
- Connections that skip layers: implicit. A node's children can be genes and
  hidden nodes of any depth at once, kept in `nodeGeneMap` and `nodeNodeMap`
  (`KPNN_Function.py:528-545`) and stacked together (`KPNN_Function.py:612`).
  The paper notes "shortcuts" to the input layer.
- Outputs or losses at inner layers: none; outputs are the label-matched
  roots (`KPNN_Function.py:654-660`).
- Parts the graph does not constrain: none; every weight is an edge or a bias.
- Other structure: dropout on inputs and on each hidden node, with a
  graph-dependent keep probability (`KPNN_Function.py:580-585`, `628-643`); a
  hook adding ±ε to one node's activation (`KPNN_Function.py:587-590`).
- Defined at: `KPNN_Function.py:566-643`.

## Connectivity mechanism

`weights` is one flat variable of shape `[E, 1]`, `E` the number of edges
(`KPNN_Function.py:548`, `594`); `interceptWeights` holds one bias per
non-input node (`KPNN_Function.py:599`). Each node owns a contiguous block of
`weights` (`weightMap`, `KPNN_Function.py:530-538`) and slices it out
(`KPNN_Function.py:611`). The input matrix is unstacked into one tensor per
gene (`KPNN_Function.py:606`); each node stacks its children's tensors
(`KPNN_Function.py:612`) and multiplies them by its block
(`KPNN_Function.py:613`). The TensorFlow graph thus holds one small op group
per node. Absent edges have no parameter and no gradient. Weights and biases
start from a standard normal (`tf.random_normal` defaults,
`KPNN_Function.py:594`, `599`).

## Interpretation

- Node weights by finite difference for every hidden node; input genes are
  not scored (`KPNN_Function.py:890`). On all test cells, the node's
  activation gets +ε, then −ε (`KPNN_Function.py:588-590`, `623-624`); the
  score is (ŷ₊ − ŷ₋)/(2ε) on output probabilities, averaged over test cells
  (`KPNN_Function.py:894-895`), ε = 0.001 (`KPNN_Function.py:65`). Signed
  scores per hidden node and output go to `tf_NumGradMeans.csv` by node name
  (`KPNN_Function.py:903-906`); R takes |score|
  (`Analysis_Scripts/Analysis_SummarizeOneRun.R:43`).
- Also written by name: each node's mean activation over the test cells of
  each class (`KPNN_Function.py:863-875`) and every edge weight and bias
  (`KPNN_Function.py:844-861`); the paper does not use edge weights.
- Across repeats (one random initialization each):
  `Analysis_Scripts/Analysis_CollectOutputs.R:77-110` stacks scores into a
  node × replicate matrix; `Analysis_Scripts/Analysis_SIM.R:49-52` keeps runs
  with test error below 0.2 and min-max scales |score| per experiment.
- Control baseline: `--control` (`KPNN_Function.py:280-313`) swaps in
  simulated counts where every gene is equally predictive (half the cells from
  the summed profile, half with each gene × 0.5 or × 2) and keeps only the
  first output. The paper's limma comparison of real vs control replicates is
  not in the repository.

## Fragile spots

- Dropout adjustment finds a node's parents with `str.match("^" + n + "$")`,
  so the node name is a regular expression (`KPNN_Function.py:632`); a name
  with `.`, `+`, or `(` can match other names or raise.
- In control mode with several outputs, edges from `outputs[1:]` are removed
  (`KPNN_Function.py:283-285`) after the pruning loop has run
  (`KPNN_Function.py:258-267`). Nodes reachable only from those outputs become
  extra roots, are appended to `nodesRanks` (`KPNN_Function.py:510`), get a
  sigmoid unit that feeds nothing, and score exactly 0
  (`KPNN_Function.py:890`). The HCA control run uses `--control` with three
  outputs (`Slurm_Scripts/run_HCA_KPNN.sh:117-123`).
- The activation table takes names from `nodes.keys()`
  (`KPNN_Function.py:872`) and values from the separate dict `nacs` returned by
  `sess.run` (`KPNN_Function.py:867`). The pairing is correct only if both
  dicts iterate in the same order; Python ≥3.7 guarantees that, the Python 2.7
  the paper used does not.
- The edge a weight stands for is implied by the genes-first stacking order
  (`KPNN_Function.py:612`), not the edge-list order `weightMap` was filled in
  (`KPNN_Function.py:536-538`); the export repeats that order
  (`KPNN_Function.py:852-857`), and no stored name ties a slot to its edge.
- Edge-list genes missing from the data, or lacking the `_gene` suffix, are
  pruned silently along with parents left without children; only the
  matched-gene count is printed (`KPNN_Function.py:241`).

## Out of scope

- Loss: class-weighted sigmoid cross-entropy per output; L2 on edge weights

- Training loop, early stopping, checkpointing (`KPNN_Function.py:730-802`).
- Data loading, log-TPM, 0–1 scaling per gene, stratified split
  (`KPNN_Function.py:172-223`, `315-446`).
- TensorBoard, memory logging, plots, SLURM loops, toy data (`Test_Data.R`).

## Paper vs code

- Graph building and the edge-swap control networks are in the paper only
  (see **Prior-knowledge graph**).
- The paper uses absolute node weights; the script writes signed ones and R
  takes |score| (`Analysis_Scripts/Analysis_SummarizeOneRun.R:43`). The paper
  says input-node weights can be read by sign; the code scores hidden nodes
  only (`KPNN_Function.py:890`).
- The Methods describe dropout on hidden and input nodes only. The code also
  raises the keep probability when a node's parents have 2 or 3 children and
  skips only children (`KPNN_Function.py:631-643`). HCA runs turn this off
  (`--disableDropoutAdjust`, `Slurm_Scripts/run_HCA_KPNN.sh:22`); TCR runs keep
  it (`Slurm_Scripts/run_TCR_KPNN.sh:35`).
- The paper simulates as many control cells as the TCR data has; the code caps
  them at min(cells, 2 × minibatch) (`KPNN_Function.py:288`, default
  minibatch 1000 at `KPNN_Function.py:44`).
- Smaller details: weights and biases start from a standard normal
  (`KPNN_Function.py:594`, `599`); L2 is divided by the batch size and skips
  biases (`KPNN_Function.py:649-651`); TensorFlow 1.13.1 is pinned, not
  1.3.1 (`Requirements_python.txt:1`).
